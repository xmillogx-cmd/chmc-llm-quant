# TDA-сравнение CHMC v6 по 3 моделям (BPW = 4.2875, = GPTQ)

Дата: 2026-08-18. Все прогоны — без ошибок. Конфиг сжатия везде один:
`strict_sequential=true, dampening=0.05, residual_bits=4, group_size=128`.
Метод TDA: kNN VR (k=32), 512 точек/облако, seed=42; H_0 union-find + GUDHI-кроссчек
(расхождений 0 везде); H_1 — GUDHI SimplexTree; eps* = медианное NN-расстояние.

## Наблюдения

1. **Деградация PPL растёт при уменьшении модели**: 1.071 (1.1B) → 1.168 (0.5B) →
   1.186 (135M). При равном BPW=4.2875 CHMC v6 «дороже» всего для самой маленькой сети —
   согласуется с общим паттерном: у мелких моделей меньше избыточности на бит.
2. **Косинусы pre/post высокие во всех трёх (>0.986)**: направление потоков почти не
   изменилось; деградация PPL не видна в построчном выравнивании — она в деталях, которые
   косинус не ловит (отсюда и TDA-путь).
3. **H_1 не «упрощается»**: у smollm после сжатия появляются новые циклы (gain 14 vs drop 1),
   у qwen баланс почти равный (9/8), у tinyllama тоже больше gain (4/8). Топология либо
   сохраняется, либо становится сложнее — «схлопывание» манифольда не наблюдается.
4. **Effective rank весов почти не сдвигается во всех трёх моделях** (+0.9%…+1.2%):
   остаточная квантизация держит хвост спектра; спектральный след компрессии слабый.
5. **corr(W_1(H1), 1−cos)** умеренная (0.25–0.64): топологическое изменение по блокам
   частично связано с потерей выравнивания, но не сводится к ней. Честный прокси —
   delta-PPL на блок не измерялся.

## Оговорки сопоставимости

- **Сырые W_1 между моделями НЕ сравнивать**: разные масштабы eps*/активаций
  (smollm ~37–1290, qwen ~5–89, tinyllama ~0.1–32). Сопоставимы: косинусы, PPL ratio,
  eff-rank, b1 drop/gain, корреляции внутри модели.
- b_k(eps*) считает essential-классы живыми (death=inf) — задокументированная оговорка.
- Случайный SVD в сжатии: пересборка .pt даёт слегка разный compressed PPL
  (smollm: 25.43 → 25.27); baseline детерминирован.

## Вычислительное окружение

Весь прогон (collect + analyze + project_3d) шёл на **CPU**: venv содержит
`torch 2.13.0+cpu` (CPU-only сборка, CUDA в этом окружении нет). Время: collect ~4–19 мин/модель,
analyze ~40–60 с/модель. Если нужна GPU-скорость — поставить CUDA-сборку torch в venv;
код менять не нужно.

## Артефакты

- `results_v6\tda_analysis\` — ровно 5 файлов на модель, имена с суфиксом `<model>`:
  `tda_activations_*.pt`, `tda_layer_table_*.csv`, `tda_summary_*.json`,
  `tda_diagrams_*.png`, `tda_report_*.md` (15 файлов на 3 модели).
- `results_v6\tda_3d\<model>_activations_3d.png` — 3D-проекции активаций pre/post:
  PCA-3D на центрированном объединении [pre; post] (общая основа для обоих облаков),
  блоки [0, n/4, n/2, n−1]; синие = pre (FP), оранжевые = post (CHMC v6), серые линии —
  соответствие по токенам (строка i в pre та же калибровочная позиция, что и строка i в post).
- Логи шагов: `tda_analysis\logs\` (collect/analyze/project3d, имя с моделью и временем) — не артефакты.
