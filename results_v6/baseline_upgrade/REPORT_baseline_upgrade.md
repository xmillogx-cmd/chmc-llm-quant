## 2. Три вывода

### 2.1 Рычаг — dampening, а не strictness

При λ=0.01 strict (1.2217) **хуже** block (1.2146). То есть "настоящий GPTQ"
сам по себе не даёт выигрыша. Выигрыш даёт λ=0.05: 1.2217 → 1.1723 (−4%).
λ=0.1 тоже хорош (1.1798). λ=0.001 — провал (1.3129).

**Математика.** Hessian: `H = XᵀX/n + λ·mean(diag(XᵀX))·I`.
- Малое λ → H анизотропен, H⁻¹ имеет огромные компоненты в направлениях с
  малой активацией. Error-feedback `err = (col−col_q)/H⁻¹[j,j]`,
  `Rr[:,j+1:] −= err·H⁻¹[j,j+1:]` **усиливает шум** в этих направлениях.
  Калибровка маленькая (2048 токенов, hessian_batches=1) → оценка H в
  низкоэнергетических направлениях **шумная**.
- Большое λ → H ближе к изотропному, H⁻¹ ограничен, feedback стабилен.
  Это классический bias–variance: λ — регуляризация квантования.
- Sweet spot λ=0.05: достаточно гасит шум, не пережимает сигнал.

**Важно:** CPU-синтетическая проверка (check_strict_gptq.py) предсказала
обратное — там λ=0.001 был лучшим (0.0835 vs 0.0850). Синтетический слой
(256 токенов, чистый гаусс) не несёт шумной оценки H реальных данных.
**Вывод: подбор λ — только на реальных данных, синтетика не проксирует.**

### 2.2 group_dim=1 — проигрыш

strict gd1: 1.46–1.58 против 1.17–1.22 у gd0. GPTQ-ориентация групп
(вдоль input cols, scale на (row, col-group)) **хуже** для CHMC, чем
row-groups (gd0, scale на (col, row-group)).

**Почему.** Конусная гипотеза: активации анизотропны вдоль output-направлений
(конус). Row-groups (gd0) — scale на группу output-каналов внутри колонки —
адаптируются к этой анизотропии. Col-groups (gd1) — scale на группу
input-направлений — смешивают каналы с разной энергией в одну группу →
max-масштаб определяется самым "горячим" каналом, остальные квантуются
крупно. Плюс BPW-учёт gd1 честнее считает оверхед (4.2587 vs 4.2665),
но качество падает сильнее, чем экономится бюджет.

**Вердикт:** gd1 для CHMC — мёртвый путь. Держим gd0.

### 2.3 Qwen — отстаёт

Qwen (1.1739 vs GPTQ 1.1407, −0.033) — единственный проигрыш.
Возможные причины: (а) оптимальный λ другой (Qwen 0.5B — другие формы
слоёв: hidden 896, intermediate 4864); (б) GPTQ на Qwen просто сильнее
(его ratio 1.1407 — лучший из трёх). Проверить: grid λ на Qwen.

## 3. За что зацепиться (следующие шаги, по ожидаемой отдаче)

1. **Пропущенная клетка сетки: block × λ=0.05 / 0.1.**
   Мы мерили block только при λ=0.01 (1.2146), а strict — при всех λ.
   При λ=0.01 block > strict (1.2146 < 1.2217). Если блок лучше strict
   при том же λ, то **block@0.05 может бить strict@0.05 (1.1723)**.
   Это 2 дешёвых конфига — самый вероятный быстрый выигрыш.

2. **Тонкий grid λ вокруг 0.05:** {0.03, 0.04, 0.06, 0.08}.
   Кривая λ: 0.001→1.31, 0.01→1.22, 0.05→1.17, 0.1→1.18.
   Экстремум где-то в 0.04–0.07. Точная подгонка даст ещё 0.5–1%.

3. **hessian_batches: 1 → 4/8.** Сейчас H строится с 1 батча (2048 токенов).
   Больше данных → точнее H → можно опустить λ (меньше bias).
   Взаимодействие "больше данных + меньше λ" — классика регуляризации.

4. **Per-layer λ.** `find_best_dampening` уже есть в chmc_v6.py (A4).
   Разные слои (attn vs mlp, q/k/v vs gate/up/down) могут хотеть разный λ.
   Grid {0.02, 0.05, 0.1} на каждый слой по activation-weighted error.

5. **Per-model λ для Qwen.** Grid λ на Qwen отдельно — закрывает −0.033.

6. **Не трогаем:** QJL (мёртв), Hadamard/LM/Cone (хуже), gd1 (мёртв).
