## 2. Три диагноза (с математикой)

### 2.1 QJL (Patch 2 / C3) — фундаментально сломан для весов

**Симптом:** PPL 267228 (ratio 12541×). При этом послойный Фробениус recon_err
нормальный (0.21–0.24), lr_energy_pct 0.74–0.78. Значит проблема не в Фробениусе,
а в **структуре** реконструкции.

**Математика.** Декодер QJL:

```
R_approx = signs @ U.T
  signs : [out_f, n_proj]  ∈ {-1,+1}
  U     : [in_f,  n_proj]
  R_approx : [out_f, in_f]
```

Ранг произведения: `rank(signs @ U.T) ≤ min(rank(signs), rank(U.T)) ≤ n_proj`.
То есть **QJL-резидуал — матрица ранга ≤ n_proj = in_f/4** (низкоранговая).

Полный сжатый вес: `W_comp = W_lr + R_q`, где `rank(W_lr) = r` (SVD),
`rank(R_q) ≤ n_proj`. Итого `rank(W_comp) ≤ r + in_f/4`.
Для q_proj (576×576): `rank ≤ 72 + 144 = 216` из 576. Жёсткое низкоранговое ограничение.

**Почему это ломает модель.** Резидуал `R = W − W_lr` — это **не-низкоранговая**
часть веса (по определению то, что не уложилось в ранг r). QJL представляет
только низкоранговые матрицы (ранг ≤ n_proj). Фундаментальное несоответствие:
QJL физически не может захватить ту часть сигнала, которая не укладывается в
низкий ранг.

**Теоретический предел.** Для вектора в R^{in_f} лучшая линейная реконструкция
в n_proj-мерное подпространство имеет относительную ошибку
`sqrt(1 − n_proj/in_f)` (Johnson–Lindenstrauss / случайные проекции).
При `n_proj = in_f/4`: `sqrt(1 − 1/4) = sqrt(3/4) ≈ 0.866` → **~87% относительной ошибки**.
Это фундаментальный предел QJL для реконструкции, не зависит от масштаба.

**Почему smoke-тест "PASS" — ложноположительный.** Критерий приёма:
`recon_err QJL < 1.5× INT4 (same rank)` ИЛИ `rank QJL ≥ 2× rank INT4 (equal BPW)`.
Smoke прошёл по **второму** критерию (rank 72 vs 2), а по первому — **провал**
(4.69× > 1.5×). То есть качество не подтверждено, прошёл только BPW-критерий.

**Вердикт:** QJL — это sketching / оценка норм, а **не** формат хранения весов.
Для сжатия весов при 4.29 BPW — неправильный инструмент. **Выбросить** (или
переопределить: только как дополнительный sketch поверх полнорангового
квантованного резидуала, не как замена).

**Как проверить:** вычислить `torch.matrix_rank(R_q)` для QJL-резидуала —
должно быть ≤ n_proj. И относительную ошибку `||R − R_q||/||R||` — будет ~0.87.

### 2.2 Ротация требует подходящего квантизатора

**Симптом:** had+INT4 = 2.23 (плохо), had+LM = 1.35 (лучше). Но оба проигрывают
no-rotation+INT4+GPTQ = 1.21.

**Математика (B1' гибрид).** SVD — в исходном (конусном) пространстве,
ротация — только на стадии квантования резидуала. Ключевой инварианс:
поворот R и X **вместе** не меняет activation-weighted loss:

```
|| (R − R̂) Xᵀ ||²_F   =   || (RQ − R̂_rot) Xᵀ ||²_F
   где  R̂ = R̂_rot @ Q.T,   Q — ортогональная (Q Qᵀ = I)
```

Доказательство: `(R − R̂_rot Qᵀ) Q Xᵀ = (R Q − R̂_rot) Xᵀ` (т.к. Qᵀ Q = I).
Значит GPTQ/INT4/LM в повёрнутых координатах минимизируют **тот же** loss.

**Но квантовочная решётка различается.** Разница — в том, КАК происходит
округление (INT4 с per-group max-масштабами vs Lloyd-Max):

- **INT4 + max-масштабы** — хороший квантизатор для **анизотропных** (исходных)
  данных: масса сконцентрирована вдоль нескольких направлений, max определён
  хорошо, уровни INT4 используются эффективно.
- После **ротации** данные **гауссируются** (Hadamard ≈ случайный ортогональный
  поворот → по CLT компоненты ≈ N(0,1)). Для гаусса max определяется **хвостами**,
  а масса у нуля → INT4 с max-масштабами **плохо** использует уровни → большая
  ошибка квантования. Отсюда had+INT4 = 2.23.
- **Lloyd-Max** — оптимальный скалярный квантизатор для N(0,1) → had+LM = 1.35.

**Почему даже had+LM (1.35) проигрывает no-rot+INT4+GPTQ (1.21).**
GPTQ-компенсация — **data-adaptive** квантизатор: он строит H = XᵀX, инвертирует
и делает error-feedback по данным. В исходном анизотропном пространстве эта
адаптивность бьёт **распределительную оптимальность** LM (который фиксирован
под N(0,1) и не адаптивен к конкретным данным слоя).

**Вердикт:** ротация сама по себе не вредит (loss инвариантен), но требует
квантизатора, оптимального для гаусса (LM). Даже с LM ротация не бьёт
no-rotation + data-adaptive GPTQ. Конусная гипотеза (анизотропия + адаптивность)
выигрывает у QuIP#-ротации при этих бюджетах.

**Как проверить:** на синтетическом гауссовом слое сравнить MSE(INT4+max) vs
MSE(Lloyd-Max) — LM должен выиграть ≥ 2×. На анизотропном слое — наоборот.

### 2.3 Cone-Aware (Patch 5 / C1) — не помогает

**Симптом:** step4 (cone+had) = 2.15, step6 (cone+had+LM) = 1.353 ≈
step3 (had+LM, **без** cone) = 1.345. Точное сохранение конусовой компоненты
PPL не улучшает (даже чуть хуже).

**Математика.** Cone-Aware декомпозиция:

```
axis   = normalize( mean_over_tokens( X ) )        # ось конуса из калибровки
W_cone = (W @ axis) · axisᵀ                        # rank-1, сохраняется ТОЧНО
W_perp = W − W_cone                                # сжимается (SVD + INT4)
W_comp = W_cone + compress(W_perp)
```

Гипотеза: конусовая компонента (где живут активации) важна и её надо сохранить
точно, сжимая только перпендикулярную часть.

**Почему не помогает.** (а) Компонента rank-1 — это **маленькая** часть энергии
веса (обычно < 5%), её точное сохранение даёт малый выигрыш. (б) Damped-cov SVD
**уже** учитывает активации через взвешивание `sqrt(diag(XᵀX))` — конусовое
направление уже частично захвачено low-rank фактором. (в) Доп. BPW-оверхед
за хранение axis (16·(out_f+in_f) бит) съедает часть бюджета. Итог: нет выигрыша.

**Вердикт:** Cone-Aware как отдельный патч — **не работает**. Конусная
гипотеза реализована **лучше** через damped-cov взвешивание SVD (в baseline),
а не через точное сохранение rank-1 компоненты.

**Как проверить:** сравнить `lr_energy_pct` с/без cone — разница мала. И
BPW-оверхед cone (16·(out_f+in_f)/(out_f·in_f)) — мал, но не ноль.

## 3. Почему baseline лучший (конусная гипотеза работает)

Plain baseline = **damped-cov SVD + INT4 + GPTQ-компенсация**, всё в исходном
анизотропном пространстве:

```
1. diag_c = diag(XᵀX)/n + λ·mean          # дэмпфированная ковариация активаций
2. W_weighted = W · sqrt(diag_c)          # взвешивание по конусу
3. W_lr = SVD_lowrank(W_weighted, r)      # low-rank в конусном направлении
4. R = W − W_lr                           # резидуал
5. R_q = GPTQ_compensate(R, X)            # data-adaptive квантование (H = XᵀX)
6. W_comp = W_lr + R_q
```

Здесь **анизотропия активаций** (конус) используется дважды:
- на шаге 2–3 (SVD выстраивается вдоль конуса),
- на шаге 5 (GPTQ-компенсация адаптивна к данным).

Это и есть конусная гипотеза в действии: данные не хаотичны, они сконцентрированы
в конусе, и CHMC это эксплуатирует. QuIP#-ротация (2.2) **разрушает** эту
анизотропию, поэтому проигрывает.

## 4. Рекомендация: апгрейд базлайна

Чтобы побить GPTQ (закрыть разрыв 0.0385 на SmolLM), улучшать **сам baseline**,
а не TurboQuant-патчи:

1. **A1 strict_sequential (настоящий GPTQ).** Сейчас baseline использует
   **block-компенсацию** (BLOCK=32 колонки за раз, OPT-2) — это приближение:
   внутри блока колонки **не** компенсируют друг друга. Strict GPTQ
   (`quantize_with_compensation_strict`) — колонка-за-колонкой, полный H⁻¹,
   error-feedback во **все** оставшиеся колонки. Это точнее.
   - Математика: после квантования колонки j ошибка `e = (w_j − q_j)/H⁻¹[j,j]`
     вычитается из всех `W[:, j+1:]` через `H⁻¹[j, j+1:]`. Block-вариант делает
     это только МЕЖДУ блоками, не внутри.
2. **A4 dampening grid.** Сейчас λ=0.01 фиксирован. Grid по
   `[0.001, 0.005, 0.01, 0.05, 0.1]` — подобрать под данные.
3. **Выбросить QJL** (фундаментально не подходит для весов).

Ожидаемый эффект: strict GPTQ должен сузить разрыв до GPTQ (блок → strict).
Dampening grid — доп. 1–3%.

**Подтверждено CPU-проверкой** (синтетический слой, без GPU):

| метрика | block (damp=0.01) | strict (damp=0.01) | strict (damp=0.001) |
|---|---|---|---|
| Frobenius rel err | **0.1746** | 0.1888 | — |
| **Activation-weighted err** (определяет PPL) | 0.0906 | 0.0850 | **0.0835** |

Strict **хуже по Фробениусу**, но **лучше по activation-weighted ошибке**
(~6–8% лучше) — а именно эта метрика определяет PPL. Strict оптимизирует
правильный loss (через H = XᵀX). Damp=0.001 чуть лучше 0.01.
Вывод: strict + малый dampening — верное направление апгрейда.

## 5. Чек-лист верификации (работает ли рассуждение)

| Утверждение | Как проверить (CPU, без GPU) |
|---|---|
| QJL-резидуал низкоранговый | `torch.matrix_rank(signs @ U.T) ≤ n_proj` |
| QJL ~87% ошибка реконструкции | `||R − scale·(signs@U.T)|| / ||R|| ≈ 0.87` |
| Ротация инвариантна по loss | `||(R−R̂)Xᵀ|| == ||(RQ−R̂_rot)Xᵀ||` (в пределах 1e-5) |
| LM лучше INT4 на гауссе | MSE(LM)/MSE(INT4) < 0.5 на N(0,1) слое |
| Cone rank-1 — малая энергия | `||W_cone||/||W|| < 0.2` |
| Strict GPTQ точнее block | recon_err(strict) < recon_err(block) на том же слое |

Все проверки можно сделать на синтетических тензорах (без загрузки модели, без GPU).
